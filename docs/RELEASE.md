# 0.14.0 版本范围与验收依据

0.14.0 在现有能力上增加默认关闭、可显式开启的模型步骤自动恢复：部分输出后遇到明确网络中断或请求超时，可以在原 run 中丢弃未完成草稿、重新生成当前步骤，保留已有完整上下文与工具结果。恢复遵守累计次数、步骤窗口、原 run 取消／总时限及每次真实请求的独立计费；未知费用继续待核，状态不确定的写效果和原生搜索不会自动重放。三种文本协议的结构化流内拒绝与传输断流分别分类，明确额度／参数／鉴权／权限错误不自动恢复。配置和接入事件见 [SDK.md](SDK.md)、[API.md](API.md)。

0.12.1 在已有 Agent 内核、执行循环、多 Agent 协作、会话引用和服务器插件之上整理模块边界，并补齐历史检查点、流式资产传输和资源容量约束。源码目录、阅读顺序与模块边界见 [ARCHITECTURE.md](ARCHITECTURE.md)。调用方继续使用编译后的 JavaScript、类型声明和必要运行资源接入，公开 SDK 入口及原有持久数据可继续使用。列表 API 改为默认有界分页，依赖单次返回全部记录的调用方需按 [API.md](API.md) 的游标迁移；其他容量默认值和兼容性说明见 [CAPACITY-OPTIMIZATION.md](CAPACITY-OPTIMIZATION.md)。尚未选择公开许可证，也未在此声明已发布到 npm。

实际测试结果由脚本生成。新增源码或更新计划不会把未执行测试自动变成通过；旧版本、旧哈希或旧时间的报告也不能证明当前编译包已验收。README 不重复固定通过数量，避免与实际日志形成两份结果。

## 本地验收

使用项目已有入口：

```powershell
npm ci --ignore-scripts
npm run check:quality
npm run verify
npm run check:host
```

`check:quality` 检查全部生产源码、测试和 TypeScript 示例的类型，再执行 lint 与格式检查；它需要安装可选包的类型声明，使用完整 `npm ci --ignore-scripts`。只运行核心时仍可以省略可选依赖并执行 `npm run check` / `npm test`。`verify` 依次进行核心构建、测试类型检查、lint、格式、源码/依赖边界检查、全部核心测试、生产依赖审计、编译后冒烟和逐项证据核对，生成 `verification/report.json`、`verification/core-acceptance.json`、`verification/audit-report.json` 及日志。SDK 的打包与独立安装验收使用 `npm run pack:sdk` 后再执行 `npm run verify:sdk`，不能用源码构建通过代替包安装验证。

`.github/workflows/quality.yml` 在 Windows Node 22/24 上执行质量检查、核心测试、当前 SDK 打包与独立安装，并验证可在无人工交互下运行的浏览器、Office、节点与宿主权限边界。需要真实交互桌面的验收继续在具备相应桌面会话的机器上单独执行。

逐项验收核对 TAP 的实际 `ok` 结果和完整汇总。失败、取消、TODO、不完整日志或未登记的核心跳过均使验收失败。仅 `scope=optional-servers` 的明确测试允许因为缺少可选 `ssh2` 跳过，记为 `not-tested-optional-dependency`，计入未验证数而非通过数。装有 `ssh2` 时，这些条目必须实际执行并通过。

可选应用宿主已有独立 `npm run verify:host` 入口。当前收尾可以复用相同实现的已有宿主证据；重新运行与否应在交付说明中如实列出。源码 ZIP 和全新源码目录重建用于维护者的可复现检查，不是调用方必须接收的 SDK 形式。

## 本次暂不开展的环境验证

保留已有实现与此前证据，本次不额外连接真实付费模型、用户业务服务器或第三方企业身份/MCP 服务，也不新增 Docker、Linux/macOS PTY、跨 OS 实机迁移和公网部署联调。协议服务、本地 SSH 服务或 Windows 本机测试均有其边界，不代表这些外部环境已经通过。

具体外部项目与状态由 `CORE-ACCEPTANCE.json` 的 `externalValidation` 和可选应用计划维护；报告原样携带这些限制，不把暂缓改写成验收通过。

## 本次不开发的能力

配置界面、完整办公编辑器和公式引擎、OCR、专门的 LSP 代码智能、更多平台的桌面控制、ESP32 和其他实物硬件均按用户要求暂缓。其他明确未实现的可选协议或隔离组合继续列在验收计划中。它们不是本次收尾的开发清单。

当前底座面向单用户可信宿主；业务账户、多租户、企业登录和分布式执行不在当前范围。native 命令及可信扩展使用宿主用户权限；Windows AppContainer 覆盖已有声明的命令/持久管道/扩展场景，隔离 PTY 和复杂工具链兼容性仍受已有明确限制。详见 [CORE-FOUNDATION.md](CORE-FOUNDATION.md)。
