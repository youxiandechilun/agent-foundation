## 运行路径变化

| 位置 | 变化 | 保留的约束 |
| --- | --- | --- |
| SQLite 查询 | Store.list 新增可选的字段过滤、数组过滤和分页；增加 count、transcriptSlice、lastAssistant、committedCost；调用处使用作用域查询 | 旧调用仍可用；字段白名单、参数绑定、rowid/seq 顺序、事务行为和原 JSON 记录保持 |
| 恢复与团队调度 | 恢复仅加载活动记录；团队冲突检查只处理当前工作区；团队轮次数单独计数 | 活动冲突、maxTurns、作用域、取消与结果收集仍执行 |
| 权限与会话 | 一次同步判定共用策略读取；一次会话工具调用共用授权集合与祖先链 | 下次调用重新读取；审批后的权限重查仍在；没有跨调用权限缓存 |
| 结构化脱敏 | 同一次 JSON 处理共用 secret 与环境凭据快照 | 下一次调用能看到凭据轮换和过期；JSON key、转义值和普通字符串仍处理 |
| MCP SSE | 删除 MCP 内重复拼接和重扫描帧的实现，复用增量解码器 | UTF-8 字节限制、空游标帧、retry 上限、分块换行、取消与 reader 释放仍处理 |
| OAuth 文件 | token、注册记录、通用 vault 共用加密读写流程 | 原文件名、binding、AAD、密钥归属和密文布局不变；提交前执行调用方的生命周期与撤权校验 |
| 工具参数 | 团队工具、Office 与桌面控制从已有 Zod 服务规则生成 JSON Schema | 服务端 parse 与 refinement 仍执行；不对调用参数自动填默认值；浏览器节点的自定义 action 保留 |
| MCP API | method/op 路由表和模块级 schema 代替重复分支 | 已知操作的返回结构保留；安装与连接结果直接读取目标声明 |

工具定义与实际服务能力对齐后，Office 创建工具可以表达服务端原有的 100,000 行、500 列上限；其他资源预算和内容约束仍由服务端执行。这是工具可表达范围的修正，不代表已测量超大文档的实际吞吐。

同时修复了一个路由问题：未知的 MCP DELETE 子路径原先可能落入删除服务器分支，现在返回 404，只有服务器实体路径执行删除。已有真实 HTTP 回归验证未知操作不会删除声明。

费用预留继续在事务中判断和写入。SQL 聚合保留 void、settled、reserved、unknown 与 UTC 日期语义；采用 TOTAL 避免 SQLite 64 位整数溢出，并拒绝超出 JavaScript 安全整数范围的累计值，以明确的费用错误结束，不写入新预留。费用 summary 原有返回字段保持。

## 测量方法与结果

热点基准在同一个 Node v22.22.0 进程比较两份真实编译代码，同输入预热一次，再交替执行五轮并取中位数。SQLite 使用真实临时数据库文件。MCP 使用实际客户端与解码路径，但 HTTP 响应来自内存流，没有外部网络或模型请求。每个场景都有结果断言。

| 场景 | 基线 ms | 重构后 ms |
| --- | ---: | ---: |
| 20 次处理 300 条结构化消息脱敏 | 1,716.99 | 10.59 |
| 10,000 条效果记录中读取同一作用域，50 次 | 2,997.92 | 5.13 |
| 10,000 条历史中读取 10 条分页，50 次 | 2,033.07 | 25.02 |
| 10,000 条消息中查最后助手消息，50 次 | 2,022.03 | 0.45 |
| 100 条策略、6 项能力的权限判定，300 次 | 248.48 | 48.15 |
| 10,000 条费用记录上的原子项目预留，30 次 | 873.38 | 28.36 |
| 256 KiB MCP 帧，以 64 字节分块输入 | 301.28 | 7.84 |

微基准刻意覆盖历史累积后的热点。差异主要来自减少全量 JSON 反序列化、环境变量扫描和增长字符串的重复扫描；不是所有请求都具有相同数据规模和瓶颈，不能把表内比例当作完整 Agent 的生产提速。结果受机器负载、JIT、GC 和文件系统缓存影响，不使用这些时间作为单元测试阈值。

### 索引的写入、空间与启动成本

另用每版五个全新数据库，交替执行；每次在一个事务中写入 10,000 条约 1 KiB 效果记录和 10,000 条约 1 KiB 助手消息。直接执行预编译 SQL，以分离索引成本和脱敏收益。写入计时含 commit、不含 close；数据库体积在正常关闭后读取。没有清空操作系统文件缓存。

| 项目 | 基线 | 重构后 |
| --- | ---: | ---: |
| 批量写入中位数 | 255.61 ms | 374.43 ms |
| 关闭后数据库大小 | 28,008,448 bytes | 29,102,080 bytes |
| 已有库重新打开中位数 | 2.10 ms | 2.01 ms |

这组数据的纯 SQL 写入耗时增加约 46.5%，体积增加约 3.9%。为每个已填充的基线数据库建立新增索引，首次打开中位数约 207.93 ms。读查询收益以写入和空间成本为代价，写多读少的部署应结合自身负载重新测量。

新增九个实体字段的部分表达式索引，以及一个会话/运行/助手消息索引。没有重写旧 JSON 数据，也没有缓存记录结果。SQL 语句缓存上限为 128 条，关闭 Store 时清理。SQLite 仍为同步操作，首次索引创建会占用启动线程；大库耗时不能从这组 20,000 条记录直接外推。
